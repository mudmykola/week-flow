# WeekFlow — правила проекту

## Ефективність: менше токенів, точковіше виконання

Пріоритет — мінімізувати витрату токенів за рахунок точкових, цілеспрямованих дій замість широкого/розвідувального виконання:

- Якщо шлях до файлу чи символу вже відомий (з контексту розмови, попередніх правок) — читай/редагуй його напряму. Не запускай `find`/`grep`/`ls` по всьому проекту, щоб "звірити" те, що вже відомо.
- Редагуй через `Edit` точковими правками (старий→новий фрагмент), а не через повне перечитування + переписування файлу, якщо міняється невелика частина.
- Не перечитуй файл одразу після власної правки — інструмент редагування вже підтверджує успіх; повторне читання витрачає токени без нової інформації.
- Typecheck/build запускай один раз після завершення пов'язаного блоку правок, а не після кожної окремої зміни.
- Не роби скріншот/перевірку в браузері після кожної дрібної CSS/тексту правки — збери кілька правок і перевір разом.
- Не делегуй в Agent/Task те, що можна зробити напряму 1-2 викликами інструментів (пошук/читання конкретного файлу). Агенти виправдані лише для дійсно широкої розвідки (>3 пошукових запитів) або незалежних паралельних гілок роботи.
- Перед тим як досліджувати щось із нуля — перевір, чи це вже не з'ясовано раніше в поточній сесії.

## Стилі компонентів

- Коли компонент має власний `<style scoped>` і його треба винести — не інлайнити правила в `app/presentation/assets/css/main.css`. Замість цього створювати окремий файл `app/presentation/assets/css/components/kebab-case-назва.css` (назва — kebab-case форма компонента, напр. `bounded-task-list.css` для `BoundedTaskList.vue`, не `BoundedTaskList.css`).
- Підключати через `@import './components/kebab-case-назва.css';` одразу після `@import 'tailwindcss'; @import '@nuxt/ui';` на самому початку `main.css` — CSS вимагає, щоб усі `@import` йшли перед іншими правилами.
- `scoped` не потрібен: класи в проєкті вже мають BEM-неймінг на рівні компонента (`.bounded-task-list__toggle` тощо), колізій не буде.
- Виняток: примітиви в `app/presentation/components/base/` (`AppButton.vue`, `IconButton.vue`) свідомо не мають локальних стилів узагалі — все живе в глобальних класах (`ui-button` і т.д.) прямо в `main.css`. Це окрема, давніша конвенція, не плутати з винесенням стилів окремого компонента.

## Git-коміти

- НІКОЛИ не додавай `Co-Authored-By: Claude ...` (чи будь-який інший AI-трейлер) у повідомлення коміту в цьому репозиторії. GitHub парсить цей трейлер і додає "Claude" в список контрибюторів репо — власник не хоче цього бачити. Це вже траплялось і довелось переписувати історію `main` (`git reset` + cherry-pick + `push --force-with-lease`), щоб виправити.
- Повідомлення коміту — лише сам автор (людина), без згадок AI-інструментів у трейлерах чи тексті.

## Плани на майбутнє

- Проект буде перенесено на GitHub.
- Після цього планується налаштувати авто-деплой у Cloudflare Workers через GitHub-інтеграцію (Cloudflare Workers Builds / GitHub Actions з `wrangler deploy`), щоб push у main автоматично деплоїв без ручного `pnpm deploy`.
- Поточний деплой: `wrangler.toml` у корені (D1-біндинг `weekflow-db`, preset `cloudflare-module`). Це залишиться основою для CI-конфігурації.
